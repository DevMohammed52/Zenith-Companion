# Codebase Map

Updated: 2026-05-16

This is the quick map future chats should read before working in Zenith Companion.

## App Structure

- `src/app`: Next.js App Router pages and route handlers.
  - Public pages include dashboard, profiles, settings, databases, guilds, conquest, museum, planning tools, and world/combat pages.
  - `src/app/api`: local Next API routes. These must not expose secrets.
  - `src/app/admin`: private operations pages. Keep these out of sitemap/navigation and protected.
- `src/components`: shared UI shell, sidebar, global search, profile switcher, modals, and repeated controls.
- `src/context`: app-wide providers for data, crafting, sidebar, and item modal state.
- `src/lib`: reusable contracts, profile logic, data transforms, routing/math engines, and helpers.
- `src/data`: app-consumed static or derived data that is source-controlled when cleaned.
- `src/constants`: shared constants used by UI and calculations.

## Data And Generated Files

- `public/static-data.json`: broad public IdleMMO cache consumed by frontend pages.
- `public/usage-map.json`: generated item relationship/search usage map. `npm run build` may regenerate this.
- `public/global-search-index.json`: generated search index if present; treat as generated data and verify before committing.
- Guild/conquest public outputs are generated by guild scripts and consumed by `/guilds` and `/conquest`.
- Local/raw scraper outputs belong in `local_data/` or other local-only folders unless explicitly cleaned into public app data.

## Scripts

- `scraper.mjs`: main public data scraper. It supports focused modes like conquest-only and priority scraping.
- `scripts/rebuild-usage-map.mjs`: rebuilds item relationship/search data.
- `scripts/build-enemy-weather-preferences.mjs`: builds enemy weather preference data before production builds.
- `scripts/fetch-idlemmo-guild-intelligence.mjs`: broad guild discovery/detail fetcher.
- `scripts/refresh-idlemmo-guild-public-data.mjs`: incremental guild refresh path.
- `scripts/build-guild-public-data.mjs`: converts guild data into public frontend data.
- `scripts/verify-profile-import-normalizer.mjs`: profile import contract/normalizer verification.
- `scripts/verify-guild-conquest-pages.mjs`: guild/conquest data verification.

## Workflows

- `.github/workflows/update_data.yml`: broad public cache workflow.
- `.github/workflows/update_guild_data.yml`: guild/conquest refresh workflow.
- Workflows use repository secrets for API access and coordinator/admin calls. Do not hardcode secrets.
- Scraper/guild workflows should avoid overlap and respect IdleMMO's API limit.

## Runtime Boundaries

- Vercel hosts the frontend/static app and local Next API helpers.
- GitHub Actions fetch broad public data and commit cleaned generated JSON.
- Cloudflare Workers handle optional user-triggered profile imports and shared API budget coordination.
- Browser `localStorage` stores final user profiles. The server should not persist full imported character profiles.

## Current Design Direction

- Precompute broad data whenever possible.
- Render pages from cleaned JSON and small local transforms.
- Keep profile-specific data local and merge imports carefully with manual overrides.
- Keep shared UI controls consistent across pages.
